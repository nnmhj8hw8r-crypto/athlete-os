# /release — выпуск версии на iPhone (GitHub Pages)

Пользователь вызвал /release — это и есть разрешение на коммит и push в `main` (CLAUDE.md запрещает push без явного разрешения; вызов команды его даёт только на этот выпуск).

## Шаги

1. `git status` и `git diff --stat`. Покажи пользователю список изменённых файлов одной строкой на раздел.
   Если среди них `.env*`, резервные копии (`*.backup.json`, `athlete-os-backup-*.json`, `backups/`) или
   любые личные данные о здоровье — остановись и спроси.
2. `npm run check` (в PowerShell — `npm.cmd run check`). Любая ошибка — остановись, исправь или сообщи.
   Не выпускать с красными проверками.
3. Если менялись тексты рекомендаций, расчёты питания, сна, веса или сгонки — запусти субагента
   `safety-reviewer` по диффу. Найденные нарушения — исправить до выпуска.
4. Документы: убедись, что `docs/PRODUCT_SPEC.md`, `docs/KNOWN_ISSUES.md`, `docs/DECISIONS.md`,
   `docs/TESTING.md`, `docs/ROADMAP.md` отражают изменения. Чего не хватает — допиши кратко.
5. Коммит: сообщение по-русски, первая строка — «<Раздел> vX.Y: суть», дальше 2–5 строк что изменилось.
   В конце строка `Co-Authored-By`, как требует системная подсказка о подписи коммитов.
6. `git push origin main`.
7. Контроль публикации (workflow `.github/workflows/pages.yml`, деплой 2–5 минут, кэш Pages до 10 минут):
   - если доступен `gh`: `gh run watch` по последнему запуску «Deploy to GitHub Pages»; при ошибке —
     `gh run view --log-failed`, разобрать и сообщить;
   - без `gh`: опрашивать `https://nnmhj8hw8r-crypto.github.io/athlete-os/` (запрос с `?t=<случайное>`),
     пока не сменится имя `assets/index-*.js`, затем найти в нём строку из нового кода.
8. Итог пользователю: номер коммита, что опубликовано, как обновить на iPhone (закрыть приложение
   полностью и открыть снова), что проверить на телефоне, что не проверялось.
