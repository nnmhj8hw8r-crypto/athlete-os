# Реплика: берём лучшее из образцов

Цель пользователя — собрать у себя лучшее приложение, заимствуя удачные решения у других: интерфейсы,
удобство, техники и методики. Заимствуем **идеи и устройство**, а не чужую собственность.

## 1. Разбор образца

- Скриншоты — рассмотреть каждый. Ссылки — открыть во встроенном браузере (`get_page_text`/`read_page`),
  без входа в чужие аккаунты и без скачивания файлов без разрешения.
- Для каждого экрана записать: что на нём, зачем пользователю, какие приёмы делают его удобным
  (структура, порядок действий, жесты, крупные цели нажатия, пустые состояния, подсказки, скорость ввода).
- Отдельно — содержание (техники, упражнения, методики, цифры): что это, откуда, есть ли источник.

## 2. Что можно и что нельзя

| Берём (своими силами) | Не берём |
|---|---|
| Раскладку экранов, порядок шагов, жесты, типы элементов | Логотипы, название, фирменные картинки, иллюстрации, фото, видео |
| Идею функции («таймер отдыха после галочки») | Тексты, описания, базы данных образца целиком |
| Общую стилистику (тёмный фон, крупные кнопки) — как направление | Точную копию дизайна «пиксель в пиксель» и платный контент |
| Методику — пересказ своими словами со ссылкой на источник | Выдуманные нормативы, исследования, «так говорит автор» без проверки |

Картинки — только свои (как `src/ui/BodyFigure.tsx`) или из открытых источников с проверенной
лицензией (указать её в `docs/DECISIONS.md`). Медицинские и спортивные утверждения — по правилам
CLAUDE.md: без назначений добавок и лекарств, без обезвоживания, без диагнозов, факт ≠ предположение.

## 3. Перенос в приложение

1. Сопоставить с текущим приложением: какой раздел (`src/features/<раздел>`), что уже есть, чего нет.
   Использовать существующие компоненты (`src/ui/components.tsx`, `Modal`, `TopBar`, стили `src/styles.css`).
2. Пересказать пользователю, как понял, задать уточняющие вопросы (что именно понравилось, что не нужно),
   предложить план — по приоритету «польза / затраты», минимально достаточные изменения.
3. После согласия — реализовать по CLAUDE.md (изменение данных — через скилл `db-migration`), проверить
   `npm run check` и в браузере на 375×812, показать скриншоты.
4. Записать в `docs/INSPIRATION.md` строку: дата, образец (название/ссылка), что взяли, где в коде, что
   сознательно не брали. В `docs/DECISIONS.md` — решение, если оно меняет поведение.

## 4. Ответ пользователю

Кратко: что понравилось в образце и почему это работает, что переносим, что не переносим и почему,
что сделано и как проверить на iPhone.
