# CLAUDE.md — правила работы над Personal Athlete OS

Пользователь практически не программирует. Отвечай по-русски, объясняй важные решения простым языком,
сам проверяй качество и поддерживай документацию в актуальном состоянии.

## Обязательный порядок каждой сессии

1. Прочитать: `docs/PRODUCT_SPEC.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/KNOWN_ISSUES.md`
   (при необходимости `docs/ROADMAP.md`, `docs/TESTING.md`).
2. Проверить `git status` и текущую ветку. Незакоммиченные изменения пользователя не трогать без спроса.
3. Изучить код, который затрагивает задача, и предложить **минимально достаточное** изменение.
4. **Не переписывать проект заново** и не менять стек без явной причины, записанной в `docs/DECISIONS.md`.
5. После изменений: `npm run check` (типы, линтер, тесты, сборка). При изменении интерфейса — проверить
   в браузере. Не утверждать, что проверено то, что не проверялось.
6. Обновить документы, если изменилось поведение, архитектура или ограничения.

## Запреты

- Не делать push, не публиковать приложение, не создавать платные ресурсы без явного разрешения.
- Не коммитить `.env`, ключи, экспортированные резервные копии и любые личные данные о здоровье.
- Не передавать `PEREK_API_KEY` (и будущие ключи) в клиентский код, HTML, бандл, логи или ответы API.
- Не просить пользователя прислать ключи в чат.
- Не придумывать исследования, ссылки, нормативы, статистику; не выдавать предположение за факт.
- Не назначать лекарства и рецептурные препараты, не предлагать вещества из запрещённого списка WADA.
  Не ставить диагнозы (в том числе «перетренированность» по единичной записи).
- **Личные рекомендации разрешены** (решение пользователя 24.10.2026, DECISIONS 86) — о добавках и о сгонке
  веса, но только в «личном режиме», который пользователь включает сам, и по правилам:
  каждая рекомендация — с реальным источником (консенсус IOC по добавкам — Maughan 2018, PMID 29540367;
  ISSN о сгонке в единоборствах — Ricci 2025, PMID 40059405; другие — только проверенные через PubMed),
  уровнем доказательности и пометкой риска («низкий / умеренный / высокий»); высокий риск (острая
  дегидратация, сауна, диуретики, резкое ограничение питания) показывается как риск с предупреждением,
  а не как совет по умолчанию; добавки — только с пометкой о проверке на допинг (сертификация партии).
  Без личного режима приложение по-прежнему ничего не назначает автоматически.
- Не создавать фиктивные данные спортсмена в интерфейсе.

## Устройство кода (кратко, подробно — docs/ARCHITECTURE.md)

- `src/domain/` — чистая бизнес-логика и схемы данных (zod). Без React и Dexie. Здесь расчёты КБЖУ,
  сна, дат, резервной копии, сводки для ИИ. Каждое изменение логики — с unit-тестом рядом (`*.test.ts`).
- `src/data/` — IndexedDB через Dexie (`db.ts` — схема и версии, `repo.ts` — сохранение/удаление).
  Страницы пишут данные только через `saveEntity`/`deleteEntity` и функции этого слоя.
- `src/features/<раздел>/` — страницы и формы. `src/ui/` — общие компоненты, стили в `src/styles.css`.
- `shared/` — общий код клиента и сервера (контракт каталога продуктов, проверка EAN).
- `server/` — Fastify: прокси к Perek.us и раздача сборки. Дневники от сервера не зависят.

## Правила изменений

- Две иконки (DECISIONS 105): `main` — основное приложение, ветка `dev` — бета для проверки новых функций (`/beta/`, отдельная база).
  Новое и сомнительное сначала в `dev`; push в любую ветку — только по команде пользователя.

- При каждом выпуске — запись в `src/domain/changelog.ts` (пункты для окна «Что нового» и заметки для разработчика) и новый `APP_VERSION`.

- Все даты/время — через `src/domain/time.ts`, часовой пояс `Europe/Moscow` (`src/config.ts`).
  Моменты хранятся в UTC ISO, календарные дни — строкой `YYYY-MM-DD` по Москве.
- Изменение структуры данных: **новая** `db.version(N+1)` в `src/data/db.ts` (старые версии не трогать),
  `DATA_SCHEMA_VERSION` и миграция копий в `src/domain/backup.ts`, тесты, запись в `docs/DECISIONS.md`.
- Записи питания хранят снимок пищевой ценности — не пересчитывать историю при изменении продукта.
- Значения на 100 г и на 100 мл не смешивать, мл ↔ г без плотности не пересчитывать.
- Новые тексты интерфейса — на русском, с понятными пустыми состояниями и сообщениями об ошибках.
- Не добавлять зависимости без необходимости; новые — только проверенные и без известных уязвимостей
  (`npm audit`).

## Команды

- `npm run dev` — разработка (Vite :5173 + API :8787); `npm run dev:lan` — то же с доступом из Wi-Fi.
- `npm run build` + `npm start` — собранное приложение на :8787.
- `npm run check` — типы, линтер, тесты, сборка (обязательно перед завершением задачи).
- В PowerShell этой машины используйте `npm.cmd`/`npx.cmd`, если `npm` блокируется политикой скриптов.

## Автоматизация Claude Code (`.claude/`)

- Хуки (`.claude/settings.json`, скрипты в `.claude/hooks/`): правка `.env`, резервных копий и
  сгенерированных `referenceFoods.ts` / `off-ru.json` блокируется; после правки `.ts/.tsx` — ESLint по файлу.
- Скиллы: `/release` — выпуск на GitHub Pages (это и есть разрешение на push); `db-migration` — порядок
  изменения структуры данных; `/replica` — разбор присланных образцов и перенос лучшего, журнал —
  `docs/INSPIRATION.md`.
- Субагент `safety-reviewer` (модель Sonnet) — проверка запретов перед выпуском, только когда менялись
  рекомендации, расчёты или работа с ключами.
- MCP `context7` (`.mcp.json`) — актуальная документация библиотек. GitHub — через `gh` (вход делает пользователь).
