# Personal Athlete OS

Личная offline-first система подготовки спортсмена (дзюдо до 73 кг, самбо до 71 кг): питание, тренировки,
сон и восстановление, календарь сезона, масса тела, добавки, библиотека источников, резервная копия и
сводка для ручного анализа в Claude / ChatGPT. Версия 0.1 — рабочая демоверсия для одного человека.

Данные хранятся **только в браузере** на устройстве (IndexedDB). Синхронизации между телефоном и компьютером
пока нет — переносите данные резервной копией (раздел «Ещё → Резервная копия»).

## Что нужно

- Node.js 22.18 или новее (проверено на 24.20). Установка на Windows: `winget install OpenJS.NodeJS.LTS`.
- Платные сервисы и ключи **не нужны**. Ключ Perek.us необязателен.

## Запуск на компьютере

Первый раз:

```bash
npm install
```

Обычный запуск (собранное приложение + сервер, работает офлайн-кэш):

```bash
npm run build
```

```bash
npm start
```

Откройте http://localhost:8787.

Режим разработки (автообновление при правке кода): `npm run dev`, затем http://localhost:5173.

## Открыть на телефоне (та же Wi-Fi-сеть)

1. Узнайте IP компьютера: в PowerShell `ipconfig` → «IPv4-адрес», например `192.168.1.20`.
2. Запустите сервер так, чтобы он был доступен в сети: в файле `.env` укажите `HOST=0.0.0.0`
   (скопируйте `.env.example` в `.env`), затем `npm run build` и `npm start`.
   Либо в режиме разработки: `npm run dev:lan` (адрес будет `http://<IP>:5173`).
3. На iPhone откройте `http://<IP компьютера>:8787`. Windows может спросить разрешение для Node.js
   в брандмауэре — разрешите для частной сети.

Ограничения доступа по `http://<IP>` (не HTTPS) — браузер считает такой адрес небезопасным:

- Service Worker не регистрируется → офлайн-открытие на телефоне по этому адресу **не работает**;
- камера для сканирования штрихкода недоступна → вводите цифры вручную;
- данные, введённые на телефоне, хранятся в браузере телефона отдельно от компьютера.

Для ежедневного использования на iPhone — публикация на GitHub Pages (следующий раздел).

## iPhone: публикация на GitHub Pages (бесплатно, HTTPS)

Сборка публикуется автоматически файлом `.github/workflows/pages.yml` при каждом push в ветку `main`:
сначала проверка типов, линтер и тесты, затем сборка с путём `/<имя репозитория>/` и публикация.

Один раз в настройках репозитория на GitHub: **Settings → Pages → Source: GitHub Actions**.
Адрес приложения: `https://<логин>.github.io/<имя репозитория>/`.

Установка на iPhone: открыть адрес в Safari → «Поделиться» → «На экран „Домой“». После первого открытия
приложение работает без интернета, камера сканирует штрихкоды.

Что работает на Pages: всё, кроме сервера. Штрихкоды ищутся в Open Food Facts напрямую из браузера;
поиск по названию (Perek.us) недоступен. Данные хранятся только на телефоне — на GitHub попадает
код, а не дневник. На бесплатном тарифе GitHub репозиторий для Pages должен быть публичным:
не кладите в него `.env`, экспорт копии и любые личные файлы.

## Perek.us (поиск продуктов и штрихкодов) — необязательно, нужен свой сервер

Без ключа приложение полностью работает: штрихкоды ищутся в Open Food Facts, продукты можно ввести
вручную, поиск по названию показывает понятное сообщение. Если ключ подключён, штрихкод сначала
ищется в Perek.us, а если товара там нет — в Open Food Facts.

Чтобы подключить:

1. Получите ключ на https://perek.us/developers (бесплатный тариф: 50 карточек/штрихкодов и 500 запросов
   в день, 20 запросов в минуту, только некоммерческое использование, обязательна ссылка «Данные: perek.us»).
2. Скопируйте `.env.example` в `.env` и впишите `PEREK_API_KEY=ваш_ключ`. Файл `.env` не попадает в Git.
3. Перезапустите сервер (`npm start` или `npm run dev`). В логе появится «поиск продуктов включён».

Ключ читается только сервером (`server/perek.ts`) и передаётся только в заголовке `X-Api-Key`
к perek.us. В браузер, сборку и логи он не попадает. Не присылайте ключ в чат.
