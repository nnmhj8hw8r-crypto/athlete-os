# Принятые решения

Формат: решение — причина — рассмотренные альтернативы. Новые решения добавляются в конец.

## 2026-10-22 — v0.1

**1. Новый проект на React + TypeScript + Vite.** Папка была пустой; стек задан требованиями.
Альтернатива — Next.js: серверный рендеринг здесь не нужен и усложнил бы офлайн-режим.

**2. Хранение в IndexedDB через Dexie, offline-first.** Работает без сервера и сети, бесплатно, есть версии
схемы. Альтернативы: localStorage (мало места, нет индексов), PostgreSQL/облако (лишняя инфраструктура
и вопросы защиты данных на этом этапе).

**3. Одни zod-схемы для форм, базы и импорта.** Правила проверки в одном месте; импорт копии проверяет
то же, что и форма. Включена русская локаль zod для сообщений без собственного текста.

**4. Снимок пищевой ценности в записи питания.** Изменение или удаление продукта не переписывает историю.

**5. Без пересчёта мл ↔ г.** Без плотности продукта это была бы выдумка. Рецепт с ингредиентами в мл
требует итоговую массу блюда.

**6. Время: хранение в UTC, ввод и показ по Europe/Moscow.** Поле `datetime-local` трактуется как
московское время независимо от пояса устройства; календарные дни — строкой по Москве. Альтернатива
(время устройства) ломала бы даты соревнований в поездках.

**7. Perek.us только через локальный сервер.** Ключ остаётся в переменной окружения сервера. Свой лимит
запросов и кэш берегут бесплатную квоту. Формат ответа по штрихкоду не опубликован — разбор с запасом,
всё непонятное считается ошибкой, а не «примерным» продуктом.

**8. Любой внешний продукт сохраняется только после подтверждения пользователем.** Похожие
совпадения явно помечаются. Альтернатива (автосохранение лучшего совпадения) отклонена.

**9. Сервер на Fastify запускается встроенной поддержкой TypeScript в Node.js (≥ 22.18), без сборки
сервера.** Меньше зависимостей. Ограничение: в серверном коде нельзя использовать enum и другой
«нестираемый» синтаксис (включён `erasableSyntaxOnly`).

**10. Сервер раздаёт сборку с поиском файлов на диске при каждом запросе; отсутствующий файл → 404.**
Найдено при проверке: в режиме `wildcard: false` новые файлы после пересборки отдавались как index.html,
и Service Worker закэшировал HTML вместо скрипта (белый экран). Исправлено и покрыто тестом.

**11. Hash-маршрутизация без библиотеки.** Шесть разделов; hash-адреса не требуют настройки сервера
и одинаково работают офлайн. Альтернатива — react-router (лишняя зависимость на этом этапе).

**12. Диалоги на нативном `<dialog>`.** Удержание фокуса и Esc без библиотек; на телефоне — нижняя панель.

**13. Сканер штрихкодов — @zxing/browser с динамической загрузкой.** Нативный BarcodeDetector нет в Safari
на iPhone. Библиотека (~540 КБ) грузится только при нажатии «Сканировать камерой». Ручной ввод — всегда.

**14. ИИ — только ручной перенос текста.** Без платных API и неофициальных интеграций с подписками.
Интерфейс `AiAdapter` описан, но не реализован и ни от чего не требуется.

**15. Сон: «время в постели» и «оценка сна» разделены.** Оценка показывается, только если пользователь
ввёл засыпание или пробуждения. Фазы сна не вычисляются.

**16. Vitest 4 вместо 3 и @fastify/static 10 вместо 8.** `npm audit` показал уязвимости в зависимостях
старших версий (tinypool, path traversal в @fastify/static); после обновления — 0 уязвимостей.

**17. Без PostgreSQL, аккаунтов, облачной синхронизации.** Не нужны одному пользователю сейчас;
границы слоёв оставлены для их добавления (см. ARCHITECTURE.md).

## 2026-10-22 — v0.2: iPhone через GitHub Pages

**18. Хостинг — GitHub Pages (бесплатно, HTTPS), а не VPS.** Решение пользователя: сначала бесплатный
вариант, VPS — если не хватит Open Food Facts. Pages даёт HTTPS → на iPhone работают установка на экран
«Домой», офлайн и камера. Цена решения: нет сервера → нет Perek.us и поиска по названию; репозиторий
публичный (код виден, данных в нём нет). Переезд на VPS не требует изменений кода, только другой `BASE_PATH`.

**19. Open Food Facts — напрямую из браузера, только по штрихкоду.** API штрихкода разрешает запросы с
любого сайта, поисковые API — нет (проверено). Серверный адаптер для OFF не нужен.

**20. Цепочка по штрихкоду: свой каталог → Perek.us → Open Food Facts.** Пожелание пользователя
«сначала первый источник, если нет — второй». Perek первым, потому что точнее по российским товарам.

**21. Неполные данные OFF не превращаются в продукт.** Если нет хоть одного из ккал/Б/Ж/У — показываем
название и просим ввести цифры с упаковки. Альтернатива (подставить 0) исказила бы дневник.

## 2026-10-22 — v0.3: дневник питания по образцу FatSecret

**22. Плашки приёмов пищи видны всегда, «+» в каждой.** Запрос пользователя: оформление как в FatSecret.
Структура данных не менялась (те же `mealType`), миграция не нужна.

**23. Встроенный справочник — USDA FoodData Central (SR Legacy), 150 продуктов.** Нужен поиск по названию
без сервера и без ИИ («греческий йогурт», «форель»). Источник выбран, потому что он открытый (CC0) и
проверяемый: цифры не придумываются. Русские названия — перевод описания USDA, исходное описание хранится
в поле `source`. Файл `src/data/referenceFoods.ts` генерируется скриптом; вручную цифры не править.
Альтернативы: российские таблицы состава (неясная лицензия), поиск OFF (недоступен из браузера, CORS).
Справочный продукт в каталог не сохраняется — в записи остаётся снимок и ссылка на карточку USDA.

## 2026-10-22 — v0.4: «Питание» по скриншотам FatSecret

**25. Умный поиск без сервера и без ИИ.** Стеммер Snowball для русского, словарь синонимов (картошка =
картофель, гречка = гречневая…), Дамерау — Левенштейн для опечаток (0/1/2 по длине слова; нечёткое
сравнение по началу слова — только от 5 букв), частичное совпадение ниже полного, очки истории
(10·log2(1+раз), максимум 30). Товары с брендом −15 очков, чтобы «картошка» сначала давала картофель,
а не пирожное. Причина прежних промахов: сравнение только по началу слова, нет синонимов, нет блюд в базе.

**26. Встроенная база расширена до 234 продуктов USDA + 22 блюд.** Блюда — расчёт по типовому рецепту
из ингредиентов USDA с учётом потерь при жарке (yield). Расширенный нутриент блюда указывается, только если
он известен для всех ингредиентов. Соль в блюда не добавлена — натрий занижен (см. KNOWN_ISSUES).

**27. Офлайн-база российских товаров — подмножество выгрузки Open Food Facts.** Проверено на выгрузке
22.10.2026: из 36 891 товара с отметкой «Россия» у 33 416 пищевой ценности нет совсем, с полным КБЖУ —
3 062 (0,4 МБ). Файл `public/data/off-ru.json` кэшируется Service Worker'ом. Лицензия ODbL —
`public/data/off-ru.LICENSE.txt`. Альтернативы: Perek.us (лучше покрытие, но нужен сервер и нельзя
выкачивать), FatSecret (данные РФ только в платном Premier), таблицы Скурихина (лицензия не подтверждена).

**28. Данные версии 2.** Таблица `water`; у продуктов, ингредиентов рецептов и записей — необязательные
`extra` (у записи — `extra100` снимок и `extra` порции) и `refId` (продукт базы без сохранения в каталог).
Миграция копий 1 → 2 добавляет пустую `water`; старые записи валидны без изменений.

**29. «Нет данных» ≠ 0 в статистике.** Сумма нутриента — по записям, где он известен; покрытие — доля
калорий дня с данными; «≥» при покрытии < 95%, «мало данных» при < 50%. «Полезный/неполезный сахар» не
используется: из доступных данных его не посчитать; показываются «Сахара (всего)» и «Добавленный сахар»
только при наличии у источника.

**30. Личный план считает, а не назначает.** Миффлин — Сан Жеор × коэффициент нагрузки; цель к дате —
≈7700 ккал/кг (грубая оценка). Калорийность не опускается ниже основного обмена: вместо этого честный
прогноз веса к дате. Предупреждения: темп > 1%/нед (Garthe 2011), углеводы < 3 г/кг (ACSM 2016).
Белок и доля жиров задаёт пользователь (подсказки ISSN 2017, ACSM 2016). План — в `settings`
(`nutritionPlan`), вес — в общей таблице `bodyWeights`.

**31. Вода: без протоколов сгонки.** Цель по умолчанию — 80% от EFSA (2,5 л общей воды мужчинам), своя
цель и особые дни вводит пользователь. «Водную загрузку» с последующим ограничением перед взвешиванием
приложение не рассчитывает (правило проекта: не предлагать обезвоживание) — только показывает цель,
назначенную специалистом.

**32. Быстрый ввод калорий** пишется как запись с `refId: 'quick'` (amount 100, per100 = итог) и не попадает
в историю. Незаполненные БЖУ записываются нулём — это явно сказано в форме.

**24. Неполные данные по штрихкоду → форма с подстановкой.** Вместо сообщения-тупика (решение 21
дополнено): известные значения и название переходят в форму, пустые поля дописывает пользователь.
Нули по-прежнему не подставляются.

## 2026-10-22 — v0.4.1: окна на iPhone

**33. Окна: блокировка страницы, смахивание вниз, своя запись истории.** Замечания пользователя с iPhone.
`src/ui/modalStack.ts`: пока открыто окно, `body` фиксируется (`position: fixed`) — iOS Safari игнорирует
`overflow: hidden`. Каждое окно добавляет запись в историю, поэтому жест «назад» закрывает окно, а не уходит
со страницы. Окно, закрытое кнопкой, убирает запись в следующем такте; если в том же такте открылось другое
окно (смена шага шторки), запись переходит к нему — иначе отложенный `history.back()` закрывал новое окно
(найдено при проверке). Переходы по приложению ждут, пока запись уберётся (`afterModalHistory`). Поля
формы могут сжиматься (`min-width: 0`, `minmax(0, 1fr)`), у поля даты убран системный вид.
Альтернатива — библиотека шторок (vaul и т. п.): лишняя зависимость ради трёх функций.

## 2026-10-22 — v0.5: «Тренировки» по образцу Shagulin

**34. Заимствуется удобство интерфейса, а не материалы.** Решение пользователя: взять устройство экранов
(каталог с группами, программы-карточки, экран упражнения с подходами, замеры), стиль приложения не менять.
Картинки, тексты и бренд образца не используются.

**35. Иконки упражнений — свой SVG-«человечек» со схемой мышц** (`src/ui/BodyFigure.tsx`), вид спереди или
сзади выбирается по мышцам. Открытого набора иллюстраций поз с понятной лицензией не найдено; рисунок поз
для 85 упражнений вручную — несоразмерно. Рисунок не грузится из сети и работает офлайн.

**36. Встроенный каталог упражнений в коде** (`src/domain/exerciseLibrary.ts`, id `lib:…`), как встроенные
продукты: не копируется в таблицу `exercises`. Своё упражнение с тем же названием заменяет встроенное.

**37. Данные версии 3.** Новые таблицы `programs`, `schedule`, `testDefs`, `testResults`, `photos`; индекс
`workouts.programId`. Новые поля необязательны: у подхода `durationSec`, `distanceKm`, `done`; у упражнения
тренировки `metric`; у тренировки `format`, `focus`, `programId`, `scheduleId`; у упражнения каталога
`group`, `metric`, `muscles`, `musclesSecondary`. Шаблоны копируются в программы с тем же id (при обновлении
базы и при импорте копии версии 2); таблица шаблонов остаётся ради старых копий.

**38. Программа — это план одного занятия, не многодневный цикл.** Пользователь называет программы по дням
(«Ковёр — Пн, Ср, Пт»), дни недели в программе — только подпись. Расписание — отдельно: «Неделя» (дата + утро/
день/вечер → программа). Альтернатива (дни A/B внутри программы, как в образце) отклонена как лишняя для
борца: программ может быть сколько угодно.

**39. Ковёр и день борьбы — форматы программы, а не новые виды спорта.** Вид спорта (дзюдо/самбо) остаётся
отдельным полем. Встречи — подходы типа «встречи по времени»; разминка и разбор — отметка «сделано».

**40. Текущая тренировка — черновик в `settings.activeWorkout`**, автосохранение через 0,3 с; переживает
перезагрузку. В журнал сохраняются только подходы с галочкой: подходы по плану заранее заполнены целевыми
значениями, иначе невыполненные встречи попадали бы в журнал (найдено при проверке). Правка записанной
тренировки открывается тем же экраном, её подходы уже отмечены. Старые окна «Тренировка»/«Шаблон» удалены.

**41. Замеры без нормативов.** Общие тесты для всех, своя динамика (последний, лучший, изменение, график).
Возрастные рекомендации и специальные тесты отложены пользователем; нормативы не придумываются.

**42. Фото — Blob в IndexedDB, уменьшенные до 1600 px (JPEG 0,85) + превью 320 px**, не входят в копию JSON.
Причина: копия в base64 росла бы на мегабайты с каждым фото. Оригиналы остаются в галерее телефона.

## 2026-10-22 — v0.5.1–v0.6: образец Lift Card, рисунки Everkinetic, Восстановление и Сезон

**43. Рисунки упражнений — Everkinetic (CC BY-SA 4.0), а не картинки Shagulin.** Картинки Shagulin авторские.
Открытый набор Everkinetic (github.com/everkinetic/data, лицензия проверена в LICENSE.md репозитория
22.10.2026) — 289 упражнений в `dist/exercises.json` набора, поза в момент движения, мышцы цветом не выделены. Решение пользователя:
поза в иконке + наша схема мышц на странице упражнения. 40 рисунков лежат в `public/exercises/`
(скрипт `scripts/build-exercise-images.py`, соответствие — `src/domain/exerciseImages.ts`), рядом
`LICENSE.txt`; автор и лицензия подписаны под рисунком. Изменённые файлы (убраны width/height) — под той же
лицензией. Кардио, хват и борьба в наборе отсутствуют — для них схема мышц. Папка весит 873 КБ (измерено), кэшируется для офлайна.
Для 10 упражнений точного рисунка нет — взят похожий и подписан «Похожее упражнение из набора»
(`APPROXIMATE_IMAGES`). Все источники и лицензии перечислены в «Ещё → Настройки».

**44. Раздела «Разминка» нет** (решение пользователя). «Общая» и «Суставная разминка» убраны из каталога и
стартовых планов, но остаются для показа старых записей (`RETIRED_EXERCISES`); «Акробатика и страховки» —
в «Борьбе», «Растяжка» — в «Другом». Свои упражнения с группой «Разминка» показываются в «Другом»;
значение в схеме данных оставлено, чтобы старые записи и копии оставались валидными.

**45. Чёрно-белая тема по образцу Lift Card, по настройке телефона.** Решение пользователя. Акцент = цвет
текста, цвет — только по смыслу. Сделано заменой переменных в `src/styles.css`, компоненты не менялись.
`theme-color` — отдельно для светлого и тёмного режима.

**46. Плавность — CSS-анимации без библиотек.** Появление страницы и вкладки (ключ по адресу/вкладке),
окна выезжают снизу, отклик на нажатие. У окна анимация с `fill-mode: backwards`, иначе она перекрывала бы
сдвиг при смахивании вниз. View Transitions API не используется: маршрут меняется через `hashchange`, обернуть
смену состояния в `startViewTransition` без переписывания роутера нельзя. Учитывается «уменьшение движения».

**47. Главная — сводка без кнопок добавления.** Решение пользователя: добавлять из вкладок. Графики — массы
тела и сна/самочувствия (выбор пользователя); те же карточки, что во вкладках («Сезон», «Восстановление»),
чтобы цифры совпадали. Сводка веса — `src/domain/bodyWeight.ts`, ряд сна по дням — `sleepDays`.

**48. Восстановление и Сезон доработаны без отдельного задания пользователя** (он попросил выполнить план до
конца без него): крупные карточки, графики с периодами. Смысл данных и формулировки «не диагноз» не менялись,
норм сна и веса не добавлено.

## 2026-10-22 — v0.7: интерфейс по замечаниям пользователя

**49. Анатомическая схема мышц — рисунки Wikimedia Commons (Termininja, CC BY-SA 3.0) в версии проекта wger.**
Свой «человечек» пользователь назвал непроработанным. Лицензия проверена через API Commons 22.10.2026;
файлы — `public/muscles/` (фон спереди/сзади + слой на каждую мышцу), цвета слоёв изменены, `LICENSE.txt`
рядом, подпись под схемой и в «Настройках». Предплечья и приводящие бедра в наборе отдельными слоями нет —
дорисованы полупрозрачными контурами в координатах рисунка. Цена — ~0,85 МБ в офлайн-кэше.

**50. Кардио — собственные пиктограммы поз** (`src/ui/Pictograms.tsx`). В Everkinetic кардио нет, в wger —
несколько разнородных картинок с неясной лицензией. Пиктограммы: фигура толстыми линиями, тренажёр серым,
работающие части тела подсвечены по мышцам упражнения. Это стилизация, а не анатомически точный рисунок.

**51. Плавающая нижняя панель** — по картинке пользователя: «таблетка» с пятью разделами и круглая «Ещё»,
`backdrop-filter: blur` (как в FatSecret), скользящая подсветка с пружинящей кривой. На компьютере — прежняя

## 2026-10-22 — v0.8: готовность к тренировке

**54. Данные версии 4: таблица `checkins`** (уникальный индекс по `date`, одна запись на день,

**98. «Сообщить об ошибке» не подключено**: форма Tally создана (черновик `jea4E4`), но публикацию формы и отправку данных
во внешний сервис из приложения система безопасности Claude не разрешила без явного подтверждения пользователя.

**99. Импорт копии при объединении (исправления аудита)**: две записи чек-ина на одну дату в файле копии отклоняются
при проверке (дата уникальна в базе); при объединении чек-ин из копии заменяет локальный чек-ин той же даты, а не роняет
импорт. Текущие настройки при объединении больше не перезаписываются — из копии добавляются только отсутствующие ключи
(полная замена настроек осталась в режиме «замена»). Тесты: backup.test.ts, repo.test.ts.

**100. Напоминания о добавках в приложении (исправления аудита)**: таймеры ставятся на любое оставшееся время суток
(был лимит 12 часов — приёмы дальше не напоминались); пересчёт каждую минуту (открыл приложение после времени приёма —
в течение минуты напоминание придёт); запасной путь без Service Worker исправлен и достижим; повторное уведомление
об одном приёме подавляется (ключ «дата + приём», чтобы на следующий день напоминание пришло снова без перезапуска).
Основное напоминание — по-прежнему событие календаря (решение 96).

**101. Целостность справочника блюд**: тест `referenceFoods.test.ts` проверяет, что каждый ингредиент каждого типового
блюда есть в базе; «Изменить под себя» пропускает отсутствующий ингредиент вместо падения экрана (защита на случай
ошибочной пересборки справочника).

**102. Личный режим, первая версия (v0.11, решение 86)**: переключатель «Личный режим» в «Настройках» с окном согласия
(`settings.personalMode`, `{ enabled, acceptedAt }`; структура данных не менялась). Включённый режим добавляет в «Добавки»
справочник по пяти добавкам из консенсуса IOC (Maughan 2018, PMID 29540367; тексты сверены с полным текстом PMC5867441):
кофеин, креатин, бета-аланин, бикарбонат натрия, нитрат. У каждой — для чего, схема «как в консенсусе», доказательность
словами источника, риск (низкий / умеренный), оговорки и пометка о проверке партии на допинг. Это справочник, а не назначение:
приложение не подбирает дозу под пользователя и не добавляет в его список. Данные — `src/domain/personalMode.ts`. Сгонка веса
в этой версии не сделана (источник — ISSN, Ricci 2025, PMID 40059405; сначала проверить через PubMed, высокий риск — только
как предупреждение).

**103. «Сообщить об ошибке» подключено (v0.11)**: форма Tally `jea4E4` опубликована 24.10.2026 по явному согласию пользователя.
